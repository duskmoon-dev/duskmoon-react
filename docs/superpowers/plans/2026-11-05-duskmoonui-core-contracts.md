## Priority dispositions for the coordinator

1. **Consume new surface ink without changing semantic fills.** Target surface text uses `--color-on-{primary,secondary,tertiary,info,success,warning,error}-container`; accent surface text uses `light-dark(var(--color-accent-content), var(--color-accent))`. Keep semantic fill, indicator, progress, and border variables distinct. Do not globally replace `--dm-color`, because it also drives fills.
2. **Button/Badge/Tag/Alert/Autocomplete compatibility CSS:** local `L:5871–6200` supersedes target accent outlined/ghost/text foregrounds. Compare `P(button)` outlined/ghost/text, `P(badge)` outlined/soft, `P(chip)` outlined/ghost/tonal, `P(alert)` outlined/ghost, and `P(autocomplete)` input variants. Target tonal Badge/Chip accent uses `--color-on-surface`; local accent tonal must not restore `--color-accent`. Preserve neutral/base behavior and all public props. Badge ghost is a React-only extension, absent `P(badge)`; align it consistently but do not describe it as a copied upstream ghost selector.
3. **Tabs/selected-option/tag foregrounds:** `L:3754,3789,4387,4392` uses `--color-primary`, defeating or bypassing target surface-text roles. `.tab-active`/`[aria-selected=true]` should use on-primary-container while active underline keeps primary. Cascader selected/tag rules at `L:436,565` and Select tags need the same container-content pairing. Compare `P(tabs)`, `P(cascader)`, `P(select)`, and `P(multi-select)`; adapter-only selectors are local equivalents, not identical upstream selectors.
4. **Form/validator/schema feedback:** `L:1521–1552` required markers/error labels/help/error-list and `L:6428` schema-required use error fill as surface text. Align foreground to on-error-container, preserving native validation precedence. `P(form):8–56` and `P(validator):1–56` add `--dm-validation-text` while retaining fill/content variables for checkboxes/switches. Do not replace checked fills with container ink.
5. **Single-line labels:** `P(badge):16–19` intentionally removes normal wrapping/max-inline-size/overflow-wrap/min-inline-size and sets nowrap; target Badge docs explicitly supersede old wrapping advice. Chip, Autocomplete tags, and FilterGroup labels also gain nowrap. Local Tag delegates to `.chip` and should inherit it; groups should wrap between occurrences. No blanket nowrap rule is justified for messages, form errors, or helper text.
6. **Other actual target changes:** Alert description loses opacity 0.9; Link now defines `--link-color` so hover/active derive from the selected semantic ink; RadialProgress separates `--radial-progress-color` from text, moves conic background to root, sets isolation, and places inner surface at z-index -1; base root focus exception additionally recognizes `.chat-composer-editor`. Keep these changes separate from unrelated interaction overhaul.
7. **Placeholder disposition:** inspected local InputNumber/Mentions placeholders use on-surface-variant + opacity 0.7, matching unchanged `P(input):138–140`/Textarea placeholder treatment. There is no new blanket placeholder-opacity fix in the 1.20.7→1.21.0 delta. Placeholder/native browser contrast remains NOT_RUN, not a proven regression.
